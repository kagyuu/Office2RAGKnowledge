## 1. 作るもの (30秒で把握する)

Office 文書 (Word/Excel/PowerPoint) を **RAG 向け Markdown** に変換する CLI + Python ライブラリ。

読み手は人間ではなく**チャンク分割器と埋め込みモデル**。見た目の再現は捨て、**構造** (見出し・表・シート/スライド境界・**図形内の文言**) を保つ。

### 利用者が明示的に指示した2つの要求 — これが本アプリの存在理由

1. **オートシェープ (図形) の中の文字を抜き出して Markdown に追記する。OCR は不要。**
2. **Excel は「表計算として使われている場合」と「方眼紙のように使って文書を作っている場合」の両方に対応する。判別は行わず、2種類の Markdown を出力する。**
   * 表計算モード: シートごとに `## {シート名}` の章 + Markdown テーブル
   * 方眼紙モード: シートごとに `## {シート名}` の章 + A1 から非空白セルを単純連結。空行は空行として出力 (RAG のチャンク区切りになる)
   * 図形テキストは Word/PowerPoint 同様、**章の末尾**に追記する

**この2つが動かなければ、他がすべて動いても意味がない。**

## 4. アーキテクチャ (これだけ守れば破綻しない)

```
入力 → detect_format → 形式別パーサ → 中間表現 Document → レンダラ → MarkdownOutput × 1〜2 → ファイル
                              ↑
                   ShapeTextExtractor (3形式で共有)
```

### 依存の方向 — 厳守

```
cli/  →  convert.py / batch.py / inspection.py / config.py
              ↓
        parsers/  →  ooxml/
              ↓
          models/   ←  render/
```

* **`models/` は他のどの層にも依存しない**
* **`render/` は `models/` のみに依存する** (`parsers/` `ooxml/` を import しない)
* **`parsers/` は `render/` を知らない**

これにより、レンダラの単体テストがパーサなしに書ける。テスト指示はこれを前提にしている。

### 全スプリント共通の規約

| # | 規約 |
| --- | --- |
| 1 | XML のパースは必ず `ooxml/xml_utils.py` の `parse_xml` を経由する。`etree.fromstring` を直接呼ばない |
| 2 | ZIP は必ず `ooxml/zip_reader.py` の `SafeZipReader` を経由する |
| 3 | Markdown のエスケープは**レンダラでのみ**行う。パーサは生文字列を格納する |
| 4 | データモデルは `@dataclass(frozen=True, slots=True)`、コレクションは `tuple` |
| 5 | 公開シンボルには型注釈を付ける。`Any` を戻り値に使わない |
| 6 | **ログに本文テキスト (セル値・段落・図形テキスト・title・author) を渡さない** |
| 7 | ファイル入出力は `encoding="utf-8"`、書き込みは `newline="\n"` を明示 |
| 8 | **現在時刻の取得は `DocumentMeta` 生成箇所の1箇所のみ**。パーサ・レンダラ内で `datetime.now()` を呼ばない |
| 9 | 出力順を `set` / `dict` の反復順に依存させない |
| 10 | **各タスクの【作成・編集対象ファイル】以外は編集しない。`docs/` 配下は編集しない** |

## 5. 絶対に踏んではならない落とし穴 (実測で確認済み)

**以下は実際にコードを走らせて確認した事実であり、推測ではない。誤ると中核機能が壊れる。**

### 5-1. openpyxl は空の `<v>` を書き出す (要求②に直結)

```xml
<c r="B2"><f>A2*2</f><v></v></c>
```

`<v>` は**存在するが中身が空**。

* ❌ `if v is None:` でキャッシュ値なしを判定 → **必ず誤判定する**
* ✅ `if v is None or v.text in (None, ""):`

誤ると、キャッシュ値の無いファイルで**空文字が出力され数式が失われる**。

また XML の `<f>` は先頭の `=` を**含まない** (`A2*2`)。`=` を前置して正規化すること。

### 5-2. 素朴な図形走査は同じテキストを2回拾う (中核要求に直結)

Word のテキストボックスは `mc:Choice` (新形式) と `mc:Fallback` (旧VML) の**両方に同じ内容**を持つ。

```
❌ root.findall(".//{...}txbxContent")   → 2件 (同じテキストが重複)
✅ 再帰で辿り、mc:AlternateContent では mc:Choice のみを見る → 1件
```

誤ると**すべての図形テキストが2回ずつ出力される**。

### 5-3. python-docx の公開 API では図形テキストが取れない

`document.paragraphs` はテキストボックスを**空文字として落とす**。lxml 併用は必須。

### 5-4. SmartArt は2箇所に同じテキストを持つ

`diagrams/data*.xml` (データモデル) と `diagrams/drawing*.xml` (描画結果)。**データモデル側のみ読む。**

### 5-5. Excel のシート番号とファイル名は一致しない

`sheet1.xml` の `1` は並び順ではない。**`_rels` で解決する。**

### 5-6. Excel の drawing アンカーは0起点

`xdr:from/xdr:col` `xdr:row` は0起点。A1 形式にするには `+1`。

### 5-7. Windows の `spawn` はローカル関数を pickle できない

`ProcessPoolExecutor` のワーカーは**トップレベル関数**に。CLI は `if __name__ == "__main__":` で保護。

## 6. Excel の二重出力 — 設計の中心

```
ExcelParser (解析は1回のみ)
   ↓
Document(blocks=(Sheet, ...))
   ↓                    ↓
ExcelTableRenderer   ExcelGridRenderer
   ↓                    ↓
{ステム}.table.md   {ステム}.grid.md
```

| | 表計算モード | 方眼紙モード |
| --- | --- | --- |
| 結合セル | **範囲内に複製する** | **左上を1回だけ** |
| 空行 | (テーブルの外) | **空行として出力 = チャンク境界。連続は1つに畳む** |
| 行内のセル | テーブルの列に配置 | **区切り文字なしで直結** (既定) |
| テーブル記法 | 使う | **使わない** |
| `stats` | `tables` | **`lines`** (`tables` を含めない) |
| 図形テキスト | 章の末尾 | 章の末尾 (**同じ内容・同じ位置**) |

**重要**: 中間表現は**結合を展開しない** (INV-09)。だから方眼紙モードのレンダラは**結合について何もしなくてよい**。表計算モードだけが `merged` を見て複製する。ここが両モードの差の中心。

### 方眼紙モードの期待出力 (利用者が指定した仕様そのもの)

入力シート:

| | A | B | C | D |
| --- | --- | --- | --- | --- |
| **1** | 休暇 | 申請 | 書 | |
| **2** | | | | |
| **3** | 氏名 | | 山田 | 太郎 |
| **4** | 所属 | | 開発 | 部 |

期待する出力:

```markdown
## 申請書

休暇申請書

氏名山田太郎
所属開発部
```

**このケースは U002-T4 の単体テストのケース1として必ず実装すること。**

## 7. 守るべき不変条件

| # | 条件 | 破ると何が起きるか |
| --- | --- | --- |
| INV-02 | `InlineRun.text` は**エスケープ前**の生文字列 | 二重エスケープ |
| INV-03 | 空の `InlineRun` を作らない | 冪等性比較のノイズ |
| INV-04 | `blocks` の順序 = 出力順 (脚注と位置不明図形のみ末尾へ) | 出力順が変わる |
| **INV-05** | **テキストを持たない図形は `ShapeText` を作らない** | 空の図形ブロックが出る |
| **INV-07** | **`Sheet.rows` は空行も含めて欠番なく持つ** | 方眼紙モードの段落境界が壊れる |
| **INV-08** | **`cells` は列番号昇順・非空セルのみ** | 方眼紙モードの文が乱れる |
| **INV-09** | **結合を展開しない** | 方眼紙モードで文言が反復する |
| INV-10 | `regions` は最低1要素 (空シート除く) | レンダラの分岐が壊れる |
| INV-11 | `regions` どうしが重ならない | 重複チャンクが生じる |
