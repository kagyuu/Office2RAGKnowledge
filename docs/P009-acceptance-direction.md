## 1. 本書の範囲

* 本書は次を扱う。
  * **システムテスト**: P001 の要件・非機能要件 (性能・メモリ・冪等性・互換性) を満たしているか。
  * **受け入れテスト**: 利用者・運用者の視点で、本番相当の使い方で問題なく使えるか。
  * **運用観点 (再実行)**: 同一出力先への2回目の実行 (P006 §2.3 の O-01・O-02)。
* スプリント内/モジュール間の結合テストは `docs/P008-test-direction.md` が扱う。本書では扱わない。
* テストコードの配置は `app/tests/acceptance/`。

## 2. 検証の視点

| 視点 | 内容 |
| --- | --- |
| 発注者 (利用者) | **利用者が最初に挙げた要求 (オートシェープの文字抽出)** と、追加要求 (Excel の二重出力、※CR-001・CR-002 の PDF 入力) が、実際の利用シナリオで価値を出しているか |
| RAGパイプライン構築者 | バッチ変換・パイプ処理・再実行が、パイプラインに組み込める形で動くか |
| 運用者 | エラー時に原因と対処が判るか、2回目の実行が壊れないか |
| 品質保証 | 非機能要件 (性能・メモリ・冪等性・カバレッジ・静的検査) が目標を満たすか |

## 4. 共通の前提

| 項目 | 内容 |
| --- | --- |
| 実行コマンド | `pytest tests/acceptance -v` (`app/` で実行。**P201・P205 で実行して確認済み**) |
| 性能テスト | `pytest -m perf` で別途実行する (P006 §9) |
| 出力先 | A003 を除き `tmp_path` 配下。**A003 のみ、スイート単位の一時ディレクトリを2回使う** (P006 §4.1) |
| 失敗時の扱い | **P201 では失敗を修正する** (P202〜P205)。P103 と異なり記録のみでは済ませない |

## 5. 完了判定

* **全テストが PASS になったら本フェーズは完了**とし、Closing (P301・P302) へ進む。
* 1件でも FAIL があれば P202 (修正計画) へ差し戻す。
* **P201 を3回実行しても全件合格にならない場合は停止し、`docs/.stop-report.md` に記録して人間に報告する** (Reviewer Loop の停止条件)。
