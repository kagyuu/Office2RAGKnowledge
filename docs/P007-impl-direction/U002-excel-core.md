## U002-T1: 表領域検出

### 【目的】

* 要求①。1シート内に複数の表が並んでいる場合に、空行・空列を境界として独立した表領域に分割する。

### 【作成・編集対象ファイル】

* `app/src/office2ragknowledge/parsers/excel_regions.py`

### 【参照すべき仕様箇所】

* `docs/P003-backend-spec.md` §7.4 (アルゴリズムの手順1〜7、結合を考慮した非空判定、重なりが生じないことの説明)
* `docs/P002-frontend-spec.md` §5.4.2 (外部から見える検出規則の表), §8.4 (フローチャート)
* `docs/P001-requirement.md` REQ-F-023, REQ-F-054〜057

### 【実装内容】

* 関数 `detect_regions(rows, merged, *, enabled: bool, max_regions: int) -> tuple[tuple[TableRegion, ...], bool]` を実装する。戻り値の第2要素は `region_split_abandoned`。
  * `rows: Sequence[SheetRow]` (使用範囲の全行。空行を含む)
  * `merged: Sequence[MergedRange]`
* **非空判定** (P003 §7.4): セル `(r, c)` が非空であるのは、`(r,c)` に `Cell` が存在するか、**`(r,c)` を含む `MergedRange` があり、その範囲の左上に `Cell` が存在する**とき。この判定を関数 `_is_occupied(r, c, cell_index, merged) -> bool` として実装する。事前に `cell_index: dict[tuple[int,int], Cell]` を構築しておくこと (毎回の線形探索を避ける)。
* **手順**:
  1. 使用範囲 (`min_row`, `max_row`, `min_col`, `max_col`) を求める。非空セルが1つもなければ `((), False)` を返す。
  2. `enabled` が偽なら、使用範囲全体を1領域として返す。
  3. 各行について「その行に非空セルがあるか」を判定し、**非空でない行を境界に水平分割**する。空行自体はどの領域にも含めない。
  4. 各行ブロックについて、**そのブロック内で**各列の非空判定を行い、**空列を境界に垂直分割**する。(使用範囲全体で列判定してはならない。P003 §7.4 の理由参照)
  5. 得られた矩形を、実際に非空セルが存在する範囲までトリミングする。
  6. `(top, left)` の昇順に並べる。
  7. 領域数が `max_regions` を超えたら、**結果を破棄して使用範囲全体を1領域として返し、第2要素を `True` にする**。
  8. 領域が0件かつ使用範囲が存在する場合は、使用範囲全体を1領域として返す (INV-10)。
* `TableRegion.has_header` は、この関数では**常に `True`** とする (先頭行をヘッダとして扱う既定。REQ-F-025)。
* 計算量は O(R×C)。`cell_index` の構築で全セルを1回走査し、行判定・列判定でそれぞれ走査する。

### 【実装してはいけないこと】

* レンダリング (テーブル文字列の生成)。それは U002-T3。
* openpyxl の呼び出し (この関数は中間表現のみを扱う純粋関数とする)。
* `has_header` をヒューリスティック (先頭行が文字列かどうか等) で判定すること。仕様は「先頭行をヘッダとして扱う」であり、判定は行わない。

### 【Unit Test内容】

* **ファイル**: `app/tests/unit/test_excel_regions.py`
* **ヘルパ**: `SheetRow` / `Cell` を簡潔に組み立てる補助関数を同ファイル内に作る (例: `mkrows(["AB", " C"])` のような文字列表現から行を作る)。
* **ケース (P006 §7.2 の 7〜12 を含む)**:
  1. 単一の表 (空行・空列なし) → 領域1件、範囲が使用範囲と一致。
  2. **空行1本で上下2つに分割** → 領域2件、空行は含まれない。
  3. **空列1本で左右2つに分割** → 領域2件。
  4. 空行と空列の両方 → 領域4件 (2×2)。
  5. 連続する複数の空行が境界 → 領域2件 (空行の本数によらない)。
  6. 先頭・末尾に空行がある → トリミングされ、領域の範囲に含まれない。
  7. **結合セル (A1:D1) がある行は空行と判定されず、下の表と分割されない**。
  8. **結合セルの左上に値が無い場合は、その範囲は非空とみなされない**。
  9. 1セルのみの領域も1領域として検出される。
  10. **`max_regions=2` で3領域が検出される入力 → 1領域に縮退し、第2要素が `True`**。
  11. **`enabled=False` → 領域1件 (使用範囲全体)、第2要素は `False`**。
  12. 完全に空のシート → `((), False)`。
  13. **検出された領域どうしが重ならない** (INV-11。全領域の組み合わせで矩形の交差がないことを検証)。
  14. 領域の順序が「上から下、同じ高さなら左から右」である。
  15. 行ブロックごとに列判定される (上の表が A:C、下の表が E:G のとき、それぞれ独立に検出される。使用範囲全体で列判定すると D 列が空列となり縦に切れてしまう誤りを検出するケース)。

### 【実行コマンド】

* `pytest tests/unit/test_excel_regions.py -v`

### 【完了条件】

* 上記15ケースすべてが合格する。
* **特にケース7 (結合セルの境界) とケース15 (行ブロックごとの列判定) が合格していること。** これらは P003 §7.4 が明示的に述べた要点であり、実装を誤りやすい。

## U002-T2: Excelパーサ

### 【目的】

* 要求②を含む Excel の解析。**openpyxl 1回ロード + sheet XML の lxml 1パス**のハイブリッドで `Sheet` を構築する (REQ-F-068: 解析は1回のみ)。

### 【作成・編集対象ファイル】

* `app/src/office2ragknowledge/parsers/excel.py`
* `app/src/office2ragknowledge/parsers/base.py` (Parser プロトコル。ここで作る)

### 【参照すべき仕様箇所】

* `docs/P003-backend-spec.md` §1.2 (**スパイクの実測結果と落とし穴**), §7.1 (処理順序), §7.2 (openpyxl のロードオプション), §7.3 (セル値の確定手順・キャッシュ値の判定規則・数式の正規化・共有数式・表示形式), §7.5 (打ち切り)
* `docs/P002-frontend-spec.md` §7.3.3 (Sheet の全フィールド), §7.4 (INV-07〜INV-11)
* `docs/P001-requirement.md` REQ-F-021/022/024/026〜029/051〜053

### 【実装内容】

* `base.py`: `class Parser(Protocol)` に `def parse(self, reader: SafeZipReader, filename: str, options: ConvertOptions) -> Document` を定義する。
* `excel.py`: `class ExcelParser`。
* **openpyxl のロード**: `load_workbook(path_or_buffer, data_only=True, read_only=False, keep_vba=False, keep_links=False, rich_text=False)`。`rich_text` はライブラリの版によって引数が無い場合があるため、`TypeError` を捕捉して引数なしで再試行してよい。
* **lxml パス**: `SafeZipReader` で `xl/workbook.xml` を読み、`sheets/sheet` の `name` / `sheetId` / `r:id` を得る。`xl/_rels/workbook.xml.rels` で `r:id` → シートXMLのパスを解決する (**ファイル名の数値で対応付けない**。P003 §7.6)。
* **数式情報の収集**: 各シートXMLを `read_xml` で解析し、`<c>` 要素を走査して次を作る。
  * `formula_map: dict[str, tuple[str, bool]]` — セル参照 (`"B2"`) → (数式文字列, キャッシュ値の有無)
  * **キャッシュ値の有無の判定 (最重要)**: `<v>` 要素が**存在し、かつその `text` が `None` でも空文字でもない**ときに「あり」。**`<v>` 要素の有無で判定してはならない** (P003 §1.2: openpyxl は `<v></v>` を書き出す)。
  * **数式文字列の正規化**: `<f>` のテキストは先頭の `=` を含まないため、`=` を前置する。
  * **共有数式** (`<f t="shared" si="N">`): テキストを持つ先頭セルの数式を `si` ごとに記憶し、テキストを持たない参照セルにはその数式をそのまま割り当てる (セル参照の相対調整は行わない。P003 §7.3 の★ACCEPTED★)。
* **セル値の確定** (P003 §7.3 のフローチャート):
  * 数式セルでなければ openpyxl の値を表示形式で整形して `text` に入れ、`is_formula=False`。
  * 数式セルでキャッシュ値ありなら openpyxl の値を整形して `text`、`is_formula=True`, `value_missing=False`。
  * 数式セルでキャッシュ値なしなら **`text` に数式文字列** (`=SUM(...)`) を入れ、`is_formula=True`, `value_missing=True`、シート単位のカウンタを加算する。
* **表示形式の適用** (REQ-F-026): 関数 `format_cell_value(value, number_format) -> str` を実装する。日付/時刻 → `YYYY-MM-DD` / `YYYY-MM-DD HH:MM:SS` / `HH:MM:SS`、パーセント → 100倍して `%`、通貨 → 記号を前置 (抽出できなければ数値のみ ★FIXME★)、数値 → 整数で表せるなら整数、論理値 → `TRUE`/`FALSE`、`None` → 空文字。
* **`Sheet` の構築** (不変条件を必ず守る):
  * **INV-07**: `rows` は使用範囲の最小行〜最大行を `range` で走査し、**非空セルが無い行も `SheetRow` として必ず含める**。
  * **INV-08**: 各行の `cells` は列番号の昇順で、**非空セルのみ**。
  * **INV-09**: **結合を展開しない**。`Cell` は結合範囲の左上にのみ生成する。`merged` には `ws.merged_cells.ranges` から `MergedRange` を作って格納する。
  * `hidden`: `ws.sheet_state != "visible"`。`options.include_hidden` が偽なら**そのシートをスキップする** (Sheet ブロックを作らない)。
  * 非表示の行・列: `options.include_hidden` が偽なら、`ws.row_dimensions[r].hidden` / `ws.column_dimensions[...].hidden` が真の行・列のセルを除外する。
  * `truncated_at` / `total_rows`: **打ち切りは表領域検出より前に行う** (P003 §7.5)。`options.excel.max_rows` が 0 なら無制限。
  * `regions` / `region_split_abandoned`: U002-T1 の `detect_regions` を呼ぶ。
  * `shapes`: **このスプリントでは空タプル `()` とする** (U003 で埋める)。
  * `is_empty`: 非空セルが1つもないか。
  * `formula_without_cache_count`: 上記のカウンタ。
* **警告の生成**: `Document.warnings` に次を追加する (P002 §9.3 の文言に一致させること)。
  * 打ち切り: `シート「{名前}」は {N} 行で打ち切りました (全 {M} 行)`
  * キャッシュ値なし: `シート「{名前}」に計算結果を持たない数式セルが {N} 件あり、数式を出力しました`
  * 領域上限超過: `シート「{名前}」は表領域が {上限} 件を超えたため、分割せず1つの表として出力しました`
* **`DocumentMeta` の構築**: `converted_at` は**引数で受け取る** (`parse` の呼び出し元が渡す)。パーサ内部で `datetime.now()` を呼ばないこと (規約11)。`stats` はこの時点では空でよく、レンダラ側で確定させる。
* 列番号 → A1形式の変換関数 `col_to_letter(col: int) -> str` (1起点) と、その逆 `letter_to_col` を実装する。**境界値 (25→Y, 26→Z, 27→AA, 52→AZ, 53→BA, 702→ZZ, 703→AAA) に注意**。

### 【実装してはいけないこと】

* **openpyxl を2回ロードすること** (`data_only=True` と `False` の両方で開く)。REQ-F-068 違反であり、P003 §1.2 で実測により不採用とした方式である。

## U002-T3: 表計算モードのレンダラ

### 【作成・編集対象ファイル】

* `app/src/office2ragknowledge/render/excel_table.py`

### 【参照すべき仕様箇所】

* `docs/P003-backend-spec.md` §9.2 (擬似コード・結合セルの複製・列数の統一), §9.4 (共通化の方針)
* `docs/P002-frontend-spec.md` §5.4 (全体構造・検出規則・テーブル生成規則・座標表記), §5.1 (エスケープ)

### 【実装内容】

* **`excel_base.py`**: `class ExcelRendererBase`。両モード共通の処理を持つ。
  * `render(self, document: Document, options: ConvertOptions) -> tuple[str, dict[str, int], tuple[str, ...]]` — (本文, stats, 警告) を返す。
  * 各 `Sheet` について: `## {name}` を出力 → `is_empty` なら `(空のシートです)` → そうでなければ `self._render_sheet_body(sheet, options)` を呼ぶ → 打ち切り注記 → 図形ブロック。

  * 図形ブロック: **このスプリントでは `sheet.shapes` が常に空のため出力されない。** U003 で `render/shapes.py` を呼ぶよう差し替える。**呼び出し箇所は今作っておく** (`self._render_shapes(sheet.shapes, options)` を呼び、U003 までは空文字を返すスタブとする)。

## U002-T4: 方眼紙モードのレンダラ

### 【目的】

## U002-T5: 二重出力の組み立て

### 【目的】

* 要求③。1つの `Document` から、`--excel-modes` に応じて1〜2個の `MarkdownOutput` を生成する。**解析を二重に行わないこと** (REQ-F-068)。

### 【作成・編集対象ファイル】

* `app/src/office2ragknowledge/render/__init__.py` (ディスパッチ関数を置く)

### 【参照すべき仕様箇所】

* `docs/P003-backend-spec.md` §8.1 (分岐フローチャート)
* `docs/P002-frontend-spec.md` §5.2 (出力ファイル名), §5.3 (front matter の一致範囲), §6.4 (MarkdownOutput)
* `docs/P001-requirement.md` REQ-F-064〜068

### 【実装内容】

* 関数 `render_document(document: Document, options: ConvertOptions) -> tuple[MarkdownOutput, ...]` を実装する。
* `document.format` が `XLSX` の場合:
  * `options.excel.modes` が `TABLE` → 表計算モードのみ1件
  * `GRID` → 方眼紙モードのみ1件
  * `BOTH` → **両方を生成して2件** (順序は table, grid の順に固定する。冪等性のため)
  * ファイル名サフィックスは、**モードの指定によらず** `.table.md` / `.grid.md` に固定する (P002 §5.2、§1 論点6)。
* `DOCX` / `PPTX` の場合: 共通レンダラで1件 (**このスプリントでは未実装のため、`NotImplementedError` を送出してよい**。U004 で実装する)。サフィックスは `.md`、`mode` は `None`。
* 各 `MarkdownOutput` の `meta` は、**`stats` と `warnings` 以外を共有する** (P002 §5.3)。`output_mode` は front matter 生成時に `mode` から決まるため `meta` には持たせない。
* front matter は `options.front_matter` が真のときのみ付ける。`render_front_matter(meta, mode)` を本文の前に連結する。
* **同じ `Document` を2つのレンダラに渡すこと。`Document` を複製しない** (メモリと冪等性のため)。

### 【実装してはいけないこと】

* 入力ファイルの再読み込み・再解析 (REQ-F-068)。この関数は `Document` のみを受け取り、ファイルに触れない。
* Excel 以外の形式で2件を返すこと。
* `--excel-modes` が `table` のときにサフィックスを `.md` に変えること。

### 【Unit Test内容】

* **ファイル**: `app/tests/unit/test_render_dispatch.py`
* **ケース**:
  1. **`modes=BOTH` で `outputs` が2件、順序が (table, grid)**。
  2. **サフィックスが `.table.md` と `.grid.md`**。
  3. `modes=TABLE` で1件、サフィックスが `.table.md` (`.md` ではない)。
  4. `modes=GRID` で1件、サフィックスが `.grid.md`。
  5. **2件の `meta` が `stats` 以外で一致する**。
  6. **表計算モードの front matter に `output_mode: "table"`、方眼紙モードに `"grid"` が入る**。
