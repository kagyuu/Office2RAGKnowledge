# F004 — T006 期待16 の期待をエラー表示の仕様に合わせる ※CR-001

| 項目 | 内容 |
| --- | --- |
| 由来 | `docs/P201-review-report.md` 「CR-001・CR-002 による再実行 — 第1回」§1 |
| 対象要求 | REQ-F-121, REQ-F-006 / P002 §3.4 (SCR-04)・§9.1 |
| 重大度 | 低 (アプリケーションは仕様どおり。テスト指示とテストコードの誤り) |
| 失敗テスト | `tests/integration/test_pdf_conversion.py::test_batch_with_bad_pdfs` |

## 【症状】

暗号化 PDF と破損 PDF を含むバッチで、失敗一覧に `E-005` / `E-007` の文字列が現れずテストが失敗する。終了コード 1・正常ファイルの出力・スタックトレースの非表示は期待どおり。

## 【原因】

T006 期待16 は「E-005・E-007 として失敗一覧に出る」と書いたが、**P002 §3.4 の失敗一覧 (SCR-04) は「ファイル / 種別 / 理由」を表示し、種別はエラーコードの表示名 (`パスワード保護` / `破損ファイル`) である** (既存の T004・T005 もこの表示を前提にしている)。テスト指示が上位文書と食い違っていた。

## 【修正内容】

1. `docs/P008-test-direction/T006-pdf-conversion.md` の期待16を「暗号化は種別 `パスワード保護` (E-005)、破損は種別 `破損ファイル` (E-007) として失敗一覧に出る」に改める (※F004 による修正と注記)。
2. `tests/integration/test_pdf_conversion.py::test_batch_with_bad_pdfs` の判定を、種別の表示名が出ることに改める。

**期待値の変更の正当性**: P202 の方針「失敗しているテストの期待値を変えない」は、アプリケーションの欠陥をテストの改変で隠さないための規則である。本件はテスト指示が上位文書 (P002) と矛盾しており、アプリケーションが仕様どおりであることを P201 で確認した。上位文書に合わせてテストを直すのは、この規則の対象外である。

## 【影響範囲】

テスト指示1件・テストコード1件のみ。アプリケーションコードは変更しない。

## 【対応結果】(P203)

* `docs/P008-test-direction/T006-pdf-conversion.md` の期待16を、種別の表示名 (`パスワード保護` / `破損ファイル`) で判定する記述に改めた (※F004 と注記)。
* `app/tests/integration/test_pdf_conversion.py::test_batch_with_bad_pdfs` の判定を同じ内容に改めた。終了コード 1・正常ファイルの出力・スタックトレース非表示の判定は変えていない。
* アプリケーションコードは変更していない。
* 確認: `pytest -q` で 692 passed (2回連続。`docs/test-records/20261014-0230-test-record.md`)。
