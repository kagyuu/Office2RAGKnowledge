## ADR-012 — PDF の読み取りに PyMuPDF を用い、依存を `pdf/backend.py` に閉じ込める ※CR-001

**状態**: **廃止** (2026-10-14。CR-003 により ADR-015 で置き換え) / 旧状態: 採用 (暫定。ライセンスの検討待ち) / **決定日**: 2026-10-14 / **関連要求**: REQ-F-110〜121, REQ-NF-019, REQ-NF-020 / **根拠**: 実測 (P003 §1.4)

**文脈**: PDF の論理構造 (構造ツリー) を本文テキストと結び付けて読み、文字座標・ベクター図形・暗号化を扱えるライブラリが必要。候補の PyMuPDF は **AGPL-3.0**、pdfminer.six・pdfplumber は MIT。

**決定**: **依頼者の指示 (2026-10-14) により PyMuPDF で実装する。** PyMuPDF を import してよいのは `pdf/backend.py` のみとし、他のモジュールはライブラリ非依存の型 (`pdf/model.py`) だけを扱う。

**理由**:

1. MuPDF の構造化テキスト (`TEXT_COLLECT_STRUCTURE`) が、構造要素と本文テキストを入れ子で返す。構造ツリーの順序 (REQ-F-115) をそのまま再現できる。
2. 暗号化の判定、権限の取得、復号済みで未展開のストリームの取得 (展開サイズ検査)、図形のクラスタリングが揃っている。
3. ライセンス (AGPL-3.0) は本アプリの MIT と配布条件の面で衝突しうる。依頼者は MIT を保つことを求めており、**実装後に Docling・PDF Inspector (および pdfminer.six) による代替を検討する**。差し替えの影響を1モジュールに限るため、依存を閉じ込める。

**結果**: MCR 辞書で MCID を参照するタグ付き PDF からは構造が取れず、タグなしとして変換される (P003 §1.4 #2)。代替の結論が出るまで、PyMuPDF を含めた配布物には AGPL-3.0 の条件がかかる。

**却下した案**: pdfplumber (ページをまたぐ MCID のページ情報と、要素内の出現順序が失われる。P003 §1.4 #11)。pdfminer.six は MIT で構造の対応付けも可能だが、依頼者の指示で今回は採らず、代替の検討対象とした。

**代替の検討結果 (2026-10-14)**: [research/pdf-library-alternatives.md](./research/pdf-library-alternatives.md)。Docling は代替にならない (タグを使わず、リスト・表を失い、モデルのダウンロードを要する)。PDF Inspector は単独では代替にならない (構造の階層・属性・図形が取れない)。**MIT を保つなら pdfminer.six への差し替えを推奨**。実施は依頼者の判断で、実施する場合は CR-003 として起票し、本 ADR を置き換える。
