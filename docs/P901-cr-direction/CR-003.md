# CR-003 — PDF 読み取りライブラリを PyMuPDF (AGPL-3.0) から MIT 互換のライブラリ (pdfminer.six) に差し替える

## 起票日

2026-10-14

## 起票者

* HONDOH Atsushi (本アプリのオーナー)。Claude Code セッションでの口頭依頼 (2026-10-14)
* 依頼原文: 「CR-003の起票と実行をしてください。」
* 起票の元になった検討: [`docs/research/pdf-library-alternatives.md`](../research/pdf-library-alternatives.md) の推奨 (pdfminer.six への差し替え)、および CR-001 の対処記録の備考
* 経緯: CR-001 の実装時に依頼者が「いったん PyMuPDF での実装を最後までやってください。そのあと、Docling または PDF Inspector での代替が可能か検討してください。ライセンスを MIT に保つためです。」と指示した

## 背景・課題

* CR-001 で、PDF の読み取りに **PyMuPDF** を採用した (ADR-012。状態は「採用 (暫定。ライセンスの検討待ち)」)。PyMuPDF は **AGPL-3.0 (または Artifex の商用ライセンス)** であり、本アプリ (MIT) の wheel は依存として、Docker イメージは同梱物として PyMuPDF を含む。このため配布・ネットワーク越しの提供に AGPL-3.0 の条件がかかり、**依頼者が求める「MIT を保つ」ことと両立しない**。`docs/P302-deliver.md` のリリース判定が「保留」である理由の1つでもある (10.1章①・SPEC-PDF-LICENSE)。
* 代替の検討の結果、Docling は代替にならず (タグを使わず、リスト・表を失い、モデルのダウンロードを要する)、PDF Inspector は単独では代替にならない (構造の階層・属性・図形が取れない)。**pdfminer.six (MIT) は本アプリが必要とする情報をすべて取れる**ことを確認した。
* PyMuPDF への依存は `pdf/backend.py` に閉じ込めてあるため (ADR-012)、差し替えの影響はおおむねこのモジュールに限られる。

## 変更要求の内容

* **PDF の読み取りライブラリを PyMuPDF から pdfminer.six に差し替える。** 実行時依存から PyMuPDF を外す。
* **実行時依存のライセンスを、MIT と両立するもの (コピーレフトでないもの) に限ることを要件として明文化する** (P001 の非機能要件に追加)。依存のライセンスを検査する手段 (テスト) を設ける。
* PDF 変換の外部仕様 (出力 Markdown・front matter・CLI・公開 API・エラー) は CR-001・CR-002 で定めたものから変えない。ただしバージョン画面 (SCR-02) の依存ライブラリの表示は PyMuPDF から pdfminer.six に変わる。
* PyMuPDF の制約のために設けた補正 (構造の後の Artifact の除外のための内容ストリームの走査 `pdf/content.py`) は、不要になれば取り除く。PyMuPDF の制約で「タグなし扱い」になっていた **MCR 辞書形式のタグ付き PDF は、タグ付きとして変換できるようにする**。
* Docker イメージのラベル・配布物の説明・README のライセンスの注記を更新する。

## 期待する振る舞い

* 配布物の実行時依存 (推移的な依存を含む) に、AGPL・GPL のライセンスのパッケージが含まれない。
* `pip install` で導入した環境に PyMuPDF (`pymupdf` / `fitz`) が入らない。
* CR-001 の期待する振る舞い (17項目) と CR-002 の期待する振る舞い (12項目) が、差し替え後もすべて満たされる (既存の PDF のテストがすべて合格する)。
* 構造要素が MCID を MCR 辞書で参照するタグ付き PDF が、タグ付き (`pdf_structure: "tagged"`) として、見出し等の構造を保って変換される。
* 構造ツリーの順序がページ上の位置と異なるタグ付き PDF が、構造ツリーの順序で出力される (CR-002 #10 の維持)。
* `office2rag --version` の依存ライブラリの表示に pdfminer.six の版が出て、PyMuPDF が出ない。
* 50ページの PDF の変換が 10秒以内に終わる (REQ-NF-001)。
* 変換中に外部通信を行わず、追加の外部バイナリを要しない (REQ-NF-010・REQ-NF-019)。
* Docker イメージのライセンスのラベルが MIT になる。
* 既存の Word・Excel・PowerPoint の変換結果が変わらない (既存のテストがすべて合格する)。

## 影響が想定される範囲

P901時点での見積もりであり、確定した対応範囲ではない (確定は P903 が `docs/P903-cr-records/CR-003.md` に記録する)。

* 画面: SCR-02 (バージョン画面) の依存ライブラリの表示のみ。
* API: 変更なし (公開 API の形・例外・戻り値は不変)。
* データモデル: 中間表現は不変。PDF 層の内部型 (`pdf/model.py`) に、構造ツリーの順序を保つための情報が加わる見込み。
* 依存: 実行時依存 `pymupdf` を `pdfminer.six` に置き換える。
* 関連ADR: **ADR-012 を覆す** (PyMuPDF の採用を廃止し、新しい ADR で置き換える。ADR-012 は `docs/ADR_master.md` に退避する)。ADR-013・ADR-014 の判断 (タグ付きの判定・レイアウト補正) は変えない。
* 設計書: P001 §8.3、P002 §3.2、P003 §1.4・§2.2・§4.4・§7A.2・§12A・§13・§14、ArchitectureHandbook §4-8〜4-14・§9-13〜9-15。

## 優先度の判断理由

* 影響度: 高。配布物のライセンスに関わり、すべての配布形態 (wheel・Docker) に影響する。
* 緊急度: 高。リリース判定が保留になっている理由の1つであり、依頼者が「MIT を保つ」ことを求め、即時の実行を指示している。
* ルーブリック (影響度: 高 × 緊急度: 高) を当てはめて、優先度は **高** とする。
