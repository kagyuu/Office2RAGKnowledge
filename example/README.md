# 変換サンプル (example)

インターネットで公開されている、著作権上再利用できる日本語の Office 文書・PDF を Office2RAGKnowledge 1.1.0 で Markdown に変換した結果です。アプリケーションは改修していません。

- `input/` … 変換前の文書 (取得したまま。ファイル名だけ分かりやすく付け直したものがある)
- `output/` … 変換結果の Markdown (`input/` と同じ種別ごとのフォルダ構成)

変換コマンド (既定オプションのまま、種別フォルダごとに実行):

```bash
office2rag convert input/word       -o output/word
office2rag convert input/powerpoint -o output/powerpoint
office2rag convert input/excel      -o output/excel
office2rag convert input/pdf        -o output/pdf
```

実行環境: WSL2 (Linux) + Python 3.12。変換は 10 ファイルで合計 約 2 秒、エラーは 0 件でした。

## 所見

### うまくいった点

- **Word**: 見出しスタイルが Markdown の見出し階層 (`##`〜`####`) に正しく対応し、改訂履歴などの表も GFM の表になる。チャンク分割に必要な構造は保たれている。本文から離れたテキストボックス (留意事項や図表番号) も「図形テキスト (位置不明)」として末尾に残り、取りこぼしは無い。
- **PowerPoint**: 図形内の文字 (40 個・126 個) をすべて抽出できた。OCR を使わないので文字化けや誤認識が無い。
- **Excel 表計算タイプ**: `WBS例.table.md` は 1 行 = 1 作業の Markdown 表になり、No・名称・ステークホルダー別の◎○・アウトプット・該当箇所がそのまま列として読める。RAG 用途ではそのまま使える品質。課題管理簿のタイトル (`<システム名称>`、`履歴ID` 等) が図形に書かれていても拾えている。
- **Excel 方眼紙タイプ**: `.grid.md` では、細かい結合セルに散らばった文字が読み順どおりの文章に戻る (6KB)。一方 `.table.md` は結合セルの値を列数分繰り返すため 172KB に膨れ、同じ文が数十回並ぶ。「両方出して、使う側が選ぶ」という設計どおりの対比になった。
- **PDF (タグ付き文章)**: DS-211 は「１ はじめに」→「１.１ 背景と目的」→「３．３．１ GSOダッシュボード」の見出し階層・目次・用語表が、元の構造どおりに出力された。51 ページを約 1 秒で変換。

### 気になった点 (改修候補)

1. **表セル内の `#` が二重にエスケープされる (不具合と思われる)**: `output/pdf/在留申請オンラインシステム利用申出書_記載例.md` の記号表で、`#` だけのセルが `\\#` と出力される (Markdown として表示すると `\#`)。`render/markdown.py:149` で、`render_runs()` が run ごとに `escape_line()` (行頭の `#` → `\#`) をかけた文字列に、さらに `escape_cell()` (`\` → `\\`) をかけているのが原因。この表描画は共通処理なので、Word・PowerPoint の表で、セルの run が `#`・`- `・`> `・`1. ` で始まる場合にも同じことが起きるはず。
2. **セルや図形の中の改行・段落が区切りなしで連結される**: 例として、`ＩＴマネジメントの全体像.md` の表は「プロジェクトの立ち上げ及び初動プロジェクト計画の策定デジタル庁によるレビュー…」と、作業名が 1 続きの文字列になる。DS-211 の用語表も「研究所National Institute of…」のように語がくっつく。`<br>` か空白を入れないと、検索の際に語の切れ目が失われる。
3. **方眼紙 grid モードで、隣り合うセルが区切りなしで結合される**: 「法人番号事業内容」「在留カード・特別永住者証明書番号職務上の地位」のように、ラベル同士やラベルと値がくっつく。表計算タイプのシートを grid モードで出すと (`WBS例.grid.md`)、「2プロジェクトの管理2.1プロジェクトの立ち上げ及び初動…」のように 1 行がまるごと連結される。少なくとも結合範囲や列が離れている所には空白か区切りを入れたい。
4. **Excel table モードのヘッダー判定**: `WBS例.table.md` では、シート先頭の注釈 (結合された 1 セル) が表の見出し行になり、本当の見出し (WBS / ステークホルダー / No. / 名称) は 2〜5 行目のデータ行として出る。多段ヘッダーの各段も、結合の展開で同じ値の繰り返しになる。
5. **PowerPoint のスライドタイトル**: `標準ガイドライン特有の用語・考え方集.md` は、タイトルをタイトル用プレースホルダーではなくテキストボックスで書いているため、見出しが「## スライド 3」だけになる。また「背景と目的」「適用対象」などの小見出しの図形が、それに対応する本文より後に出力される (図形の重なり順で出力しているためと思われる)。
6. **図解の意味は失われる**: 概念図 (ＩＴマネジメントの全体像、DS-920 の体制図) は、文字は全部残るが、どの箱がどの年度・どの矢印に属するかという関係は失われる。OCR を使わずテキストを抽出する方針で受け入れている範囲 (想定どおり)。
7. **PDF のページをまたぐ表が分断される**: DS-211 の用語表は、ページの区切りで別の表になる。続きの行「政府機関横断SecOpsダッシュボード」(項番 9 の定義の続き) が、次の表の「項番」列に入ってしまう。
8. **様式 PDF の読み順の乱れ**: 記載例 PDF では「入管　一郎 | 代表者の氏名」のように値とラベルが逆になり、法人番号の 1 文字ずつの枠が「7 8 9 0 1 2 法人番号 1 2 3 4 5 6 3」と並びが崩れる (元は 13 桁の連続した番号)。タグ付き PDF のタグ構造 (Excel から書き出した PDF) に従った結果と思われる。
9. **Word の章番号**: 自動の段落番号 (「第１章」「１．」) は見出しの文字に含まれず、`### はじめに` のようになる。目次には番号が残っているので、本文の見出しとの対応がやや取りにくい。
